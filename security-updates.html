meshTerm 2.3.5 - Security updates
Know when a host has security fixes waiting, and install them in one step.

1. What meshTerm checks

When you connect to a host, meshTerm checks it for available security updates, at most once a day per host. The check uses the SSH connection you already opened: nothing is installed on the host, and you don't need to do anything to turn it on.

meshTerm reports updates you can install, not whether a host is safe. It never calls a host "vulnerable": it tells you that a fix has been published for something installed there, and offers to install it.

Tailscale (free)

If Tailscale is installed on the host, meshTerm compares its version with a set of rules that meshTerm curates and publishes in its signed security feed. If the host's Tailscale has a security fix in a newer version, the host shows it.

Some Tailscale fixes are marked Recommended: they matter only inside your tailnet. These are listed in the host's Security updates screen but are not counted on the host row.

Installed packages (Pro)

With meshTerm Pro, meshTerm also compares the host's installed packages with known CVEs (published security issues) rated High or Critical, where the fix is already published in the host's own distribution repositories. A CVE that has no fix in those repositories yet is not shown, because there is nothing to install. Medium and Low issues are not shown.

The result counts packages with an update, not CVEs: one package update often fixes several CVEs at once, and installing it clears them all.

The kernel

  • A kernel fix that is available but not installed yet counts like any other package.
  • A kernel fix that is installed but waiting for a restart counts only once the fix is more than 7 days old. Most servers restart on their own schedule, so meshTerm doesn't ask for a restart the day a fix comes out.
  • Live kernel patching (Ubuntu Livepatch, kpatch) is not taken into account: a live patch doesn't change the result either way.

2. Where it shows

On the host row: a small shield pill, such as 3 updates, shows how many updates the host has waiting. There is no pill when there is nothing to install, when the host hasn't been checked yet, or when the security data is out of date (see What stays on your phone).

In Host Details > Security updates: the full list for the host.

  • One row per package, with the installed version → the fixed version, and Critical or High.
  • Under each package, the CVEs it fixes, each one linking to its entry in the distribution's security tracker.
  • A kernel row, when a kernel fix is waiting to be installed or needs a restart.
  • The Tailscale result, including any Recommended rows.
  • A footer, "Checked <time> against data from <date>", so you can see how recent the check and the data are.

From this screen you can install the updates, restart the server when it needs it, or check again.

4. What stays on your phone

The comparison happens on your iPhone or iPad. Nothing about the host is sent anywhere.

  • The security data: the phone downloads meshTerm's signed security feed from its public site on GitHub Pages. The feed is a small manifest plus one data file per release, such as debian-12. The phone fetches only the files for the releases your hosts run. GitHub sees these requests and your phone's IP address, so it could tell, for example, that this IP address has a Debian 12 host. It doesn't learn the host's name, address or packages.
  • The package list: meshTerm reads the host's installed packages over the existing SSH connection, with a read-only check that needs no root and installs nothing. The list is compared with the feed on the device and never leaves it.
  • The feed carries data, not commands. It is signed, and meshTerm ignores it unless the signature checks out. The commands meshTerm offers to run come from elsewhere (see Installing updates).
  • Old data is not used. If the security data on the phone is more than 7 days old, for example because the phone couldn't download a newer feed, meshTerm shows "Security data is out of date" with Check Again, instead of results that may be wrong.

See also the Privacy Policy.

5. Installing updates

Install Updates runs the update for you in a terminal tab on the host, so you can watch it and answer any prompt. meshTerm shows the exact command first, and nothing runs until you confirm. Copy Command copies it instead, if you'd rather run it yourself.

The command comes from meshTerm's signed host recipes (the same signed set of commands meshTerm uses for other setup steps), not from the security feed, and it names only packages that are installed on the host. It upgrades those packages and installs nothing new:

SystemCommand
Debian, Ubuntusudo apt-get update && sudo apt-get install --only-upgrade -y <packages>
Alpinesudo apk -U upgrade <packages>
AlmaLinux, Rocky Linux, RHELsudo dnf --refresh upgrade -y <packages>
  • When you sign in as root, the command runs without sudo.
  • When your account can't use sudo, the command runs through su and asks for the root password in the terminal.
  • Installing updates never restarts the server. If a fix needs a restart, Restart Server appears separately.
  • When the command finishes, meshTerm checks the host again and updates the list.
Rocky Linux and RHEL EUS

On Rocky Linux, and on RHEL with Extended Update Support (EUS), a fix that meshTerm lists may not be available from the vendor yet: Rocky Linux publishes Red Hat's fixes some time after Red Hat does. The update then installs nothing for that package. The row clears at the next check after the vendor ships the fix.

6. Restarting the server

Restart Server is a separate button. It appears only when a newer kernel with the fix is installed but not running yet, or when the host itself reports that it needs a restart.

  • meshTerm asks first: "Restart this server?"
  • It runs systemctl reboot, or shutdown -r now where that isn't available, and reboot on Alpine, with sudo when needed.
  • Every session on the server disconnects, including other people's and any tmux or mtRoam sessions: a restart ends the programs running in them. Save your work first.
  • When you reconnect, meshTerm checks the host again.

7. Updating Tailscale

For Tailscale, meshTerm shows the update command to copy, with Open Terminal to run it on the host yourself.

Updating Tailscale can drop your connection

Updating Tailscale restarts it, which can drop connections that go through your tailnet, including the one you are using to run the update. Reconnect afterwards, and meshTerm checks the host again.

  • macOS, Tailscale from the App Store: update it from the App Store on the Mac.
  • Windows: update from Tailscale's menu in the system tray, or run tailscale update in PowerShell as an administrator.

8. End of life and Ubuntu Pro

End of life: when a host runs a release that no longer gets security fixes from its distribution (for example Alpine 3.20 and 3.21 today, Debian 11, or Ubuntu 20.04 without Ubuntu Pro), meshTerm shows "This release no longer gets security fixes" beside its results. New issues won't be fixed on that release, so they can't show up as updates: upgrading to a supported release is the way to keep getting fixes.

Ubuntu Pro (ESM): some Ubuntu fixes are published only through Ubuntu Pro's Expanded Security Maintenance. meshTerm shows those fixes only on hosts that have Ubuntu Pro attached, because other hosts can't install them.

9. Supported systems

CheckSystems
Installed packages (Pro)Ubuntu 20.04, 22.04, 24.04, 26.04 and 26.10; Debian 11, 12 and 13; Alpine 3.20 to 3.24; AlmaLinux 8 to 10; RHEL 8 to 10; Rocky Linux 8 to 10 (checked against Red Hat's data)
TailscaleEvery host with Tailscale installed, including Windows and macOS

Not yet supported for the package check: Fedora, Amazon Linux, Arch and SUSE. On these, Pro shows "Package check isn't available for <system> yet". The Tailscale check still works on them.

Not covered on any system:

  • Language packages, such as pip, npm, gem or cargo packages.
  • Snaps and Flatpaks.
  • Containers and their images (see Containers for the containers themselves).
  • Software installed outside the package manager, such as from a downloaded file or built from source.

10. Checking again

meshTerm checks each host at most once a day on its own. Check Again in Security updates checks now, over the open connection. If the host isn't connected, the check runs the next time you connect to it.
