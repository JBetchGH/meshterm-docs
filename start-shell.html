meshTerm 2.3.2 - Start Shell
Your shell, on each host, without touching the server.

1. What a start shell is 2.3.2

Every account on a server has a login shell, the shell SSH starts when you sign in. Often it is bash, while the shell you actually like on that host is zsh or fish. The start shell is a per-host setting in meshTerm: meshTerm connects with your login shell as usual, then starts the shell you chose.

  • Nothing on the server changes. meshTerm doesn't run chsh, doesn't edit /etc/passwd, and on Windows doesn't change OpenSSH's DefaultShell. Other SSH clients, scripts and scp keep using the login shell. Choose Login shell again and meshTerm goes back to starting nothing extra.
  • Only shells found on the host are offered. On Linux and macOS, meshTerm reads /etc/shells and looks on your PATH for bash, zsh, fish, ksh, mksh, dash, tcsh, csh and nu. If a shell is installed twice (for example /bin/zsh and Homebrew's /opt/homebrew/bin/zsh), both are listed with their paths. On Windows the choices are Command Prompt, Windows PowerShell and PowerShell 7, when installed.
  • Checking a host's shells is one read-only command over the connection you already have. It installs nothing.
  • The login shell is always at the top of the list, marked Login shell (SSH default shell on Windows).

2. Choosing on first connect

The first time you connect to a new host, meshTerm checks which shells it has. Your session starts in the login shell straight away, so you can type while it checks.

  • The keyboard palette opens on the Start Shell list, showing "Checking shells…" and then the shells it found. Close works at any time, including while it is still checking.
  • Pick a shell and it becomes the host's start shell (see When it takes effect). Picking Login shell keeps things as they are.
  • Close (or the palette button while the list is up) keeps the login shell.
  • Either way the keyboard comes back, and meshTerm doesn't ask about that host again, on this device or, with iCloud Sync on, on your other devices.
  • If the host only has its login shell, you see "Only bash found" (or the shell's name) for a moment, and nothing is asked.

The list waits until it can be seen properly:

  • iPhone in landscape: the palette is portrait-only, so the list waits until you turn the phone to portrait. If you rotate to landscape while it is up, it goes away and comes back in portrait.
  • Another screen open (for example Files): the list waits until you close it.
  • Hardware keyboard (such as an iPad with a keyboard attached): a banner shows "Checking shells…", then "Other shells found on" your host with Choose, which opens the same list. The banner's close button keeps the login shell.

The first-connect list is only shown for ordinary terminal sessions on a host you haven't connected to before, and not on hosts that use mtRoam (see below). For hosts you already use, choose a start shell from the palette or Edit Host.

3. Changing it later

There are two ways in, and both open the same list:

  • The palette's Shell tile: on the keyboard palette's Features page, tap Shell. It opens the list for the host of the current session. The tile is dimmed when there is no live session.
  • Edit Host > Shell & Environment: under Shell, tap Start Shell. The row shows the current choice, or Login shell.

The current choice is ticked, and a pick is saved at once. Detect Again checks the host's shells again, for example after you install fish. A shell you chose earlier that the host no longer has stays in the list, marked "Not found on this host". For a host you have never connected to, the list says "Connect to this host once to see its shells."

To go back to the login shell, pick Login shell.

4. When it takes effect

  • If you haven't typed anything yet in the session, meshTerm switches right away: you see "Switching to zsh" and the session restarts in the new shell.
  • Otherwise the choice applies from your next connect, so nothing you are running is interrupted. A notice says "Start shell: zsh" and "Applies from your next connect." Tap Reconnect Now to switch now.

With tmux or psmux, a running session keeps its shells, so the choice applies to new sessions and new windows (the notice says "Applies from your next connect, to new sessions and windows."). meshTerm restarts a pane in the new shell only when it created that session on this connect, you haven't typed in it yet, and no one else is attached to it. Otherwise it leaves the session as it is.

5. tmux, psmux, Windows and mtRoam

How the start shell is used depends on the host's Persistence choice. The list's footer says which rule applies to the host.

HostWhat happens
Linux or macOS, Persistence NoneEach new connect starts in the chosen shell.
Linux or macOS, tmuxtmux starts new sessions and new windows in the chosen shell. A tmux session that's already running keeps its shells.
Windows with psmuxThe same as tmux: new psmux sessions and new windows start in the chosen shell; a running session keeps its shells.
Windows without persistenceEach new connect starts in the chosen shell.
mtRoammtRoam sessions use the login shell, for now. The choice is kept, and applies if the host switches to tmux or no persistence. Edit Host says so under Shell.

Windows and panes you create inside tmux or psmux yourself also start in the chosen shell. When you clear the start shell, meshTerm removes its setting from the tmux session on your next connect, and leaves alone any tmux setting you made yourself.

6. Sessions that use the login shell

Agent, container and one-tap sessions always use the login shell, whatever the host's start shell. That covers Agent Mode and agent sign-in, a container's Shell, Run in Terminal and other one-tap commands, and herdr sessions. These run commands meshTerm has tested against the login shell, so they stay predictable.

7. If the shell is missing

meshTerm checks that the chosen shell still exists every time it starts it. If it has been removed, or can't start, you still get a working session in the login shell, and a notice:

  • "fish isn't available on" your host, with "This session started in the login shell instead." (with tmux or psmux: "The new session or window started in the default shell instead.").
  • On psmux, a shell with a very long path can't be started by psmux: the notice says the shell "couldn't be used" and the session started in the default shell.

Tap Change Shell in the notice to open the list and pick another shell, or Login shell.

8. Environment and Secret Profiles

Variables from Shell & Environment and Secret Profiles reach the start shell when a session starts, whichever shell you chose.

Sending values into a session that is already running works only in bash and zsh. With another start shell (fish, tcsh, nu and so on, or a Windows shell), Secret Profiles says the session's start shell can't receive values while it's running; the values still apply when a session starts.

9. Good to know

  • Login messages: on a host without persistence, a session that starts a start shell doesn't show the server's message of the day (MOTD) or the "Last login" line.
  • Keep Tools on PATH: when the start shell is bash or zsh, the block is added to that shell's ~/.bashrc or ~/.zshrc too, alongside the login shell's.
  • Syncing: with iCloud Sync on, the host's start shell and the fact that you've answered the first-connect question sync with the host. Each device checks the host's shells itself.
  • Hosts meshTerm can't check: if checking a host's shells can't work there (for example, PowerShell is restricted by policy), meshTerm stops asking on first connect. You can try Detect Again from the Shell tile or Edit Host later.
  • Windows hosts whose SSH shell is MSYS2, MinGW or Cygwin aren't asked.

For hosts, persistence and the palette, see the User Guide.
